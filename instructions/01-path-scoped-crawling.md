\# InfinityCrawler Task: Optional Strict Path-Scoped Crawling

\#\# Objective

Implement an opt-in path-scoping feature in the existing InfinityCrawler library so callers can restrict a crawl to the subtree rooted at the path of the URI passed to \`Crawler.Crawl()\`.

Example start URI:

\`\`\`text  
https://example.com/ducks/  
\`\`\`

When path scoping is enabled, the crawler may crawl descendants such as:

\`\`\`text  
/ducks/  
/ducks/mallard/  
/ducks/species/wood-duck  
/ducks?sort=name  
\`\`\`

but must reject URLs outside that subtree, including:

\`\`\`text  
/  
/geese/  
/ducklings/  
/blog/ducks/  
\`\`\`

\#\# Constraints

\- Preserve existing InfinityCrawler behaviour by default. Path scoping must be opt-in.  
\- Do not redesign the crawler or introduce unrelated functionality.  
\- Follow the repository conventions documented in \`AGENTS.md\`.  
\- Do not modify autogenerated \`\_Index\_of\_\*.md\` files.  
\- Do not attempt to fix the documented pre-existing \`net461\` assembly-binding issue.

\#\# Implementation Requirements

1\. Add an appropriately named public setting to \`CrawlSettings\` that enables restriction to the starting URI's path subtree.  
2\. Derive the scope from the URI supplied to \`Crawler.Crawl()\`; do not hard-code paths.  
3\. Enforce scope at the central URI-admission point so every discovered request is subject to the same rule.  
4\. Sitemap seeding must obey the same scope. Out-of-scope sitemap URLs must not bypass filtering.  
5\. Redirect destinations must obey the same scope and must not cause an out-of-scope request.  
6\. Existing host restrictions and \`HostAliases\` behaviour must remain unchanged.  
7\. Existing fragment stripping and URI deduplication behaviour must remain unchanged.  
8\. Query strings on otherwise in-scope paths must remain valid.  
9\. Path matching must respect path-segment boundaries. A scope of \`/ducks/\` must not accidentally allow \`/ducklings/\`.  
10\. Handle \`/ducks\` and \`/ducks/\` consistently. Avoid naive prefix matching that introduces boundary bugs.  
11\. Preserve current public API behaviour when the new setting is disabled.

\#\# Testing Requirements

Use MSTest and the existing in-process \`InfinityCrawler.Tests.TestSite\` infrastructure.

Add coverage for at least:

\- Default behaviour remains unrestricted.  
\- In-scope child links are crawled.  
\- Same-host out-of-scope links are not crawled when scoping is enabled.  
\- Prefix-confusion paths such as \`/ducklings/\` are rejected for \`/ducks/\` scope.  
\- Sitemap URLs outside the scope are rejected.  
\- In-scope URLs with query strings are allowed.  
\- Redirects to out-of-scope paths are not followed.  
\- Nested descendants remain crawlable.  
\- Existing host restriction behaviour remains intact.

Use existing test helpers such as \`CrawlerTestBase.GetNoDelayRequestProcessorOptions()\` and \`GetTestSiteCrawler(siteContext)\` where appropriate.

\`\`\`powershell  
dotnet build InfinityCrawler.sln
